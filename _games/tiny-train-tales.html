Overview

This project is directly inspired by the mobile game Tiny Rails, and its purpose is purely educational. I had long been a fan of Tiny Rails and wanted to see if I could recreate it, and learn a lot along the way, which I definitely have.

This project taught me about A* pathfinding, JSON save files, inventory systems and how GameObjects relate to each other.

Systems

A* pathfinding

This is the cornerstone of the entire game and the feature I've spent the most time on. The pathfinding uses the A* algorithm, where both the start city and the destination are known in advance. It works by exploring cities one at a time, always prioritizing the one with the lowest combined cost.

Each city tracks two values: the gCost, which is the actual distance traveled from the start to reach that city, and the hCost, which is an estimate of the distance remaining to the goal. These two are added together into an fCost, and the city with the lowest fCost is always explored next. This means paths that are expensive and still far from the goal don't get prioritized, while cheaper and more promising routes get explored first.

Each city also keeps track of which city it came from, so once the destination is reached, the full path can be retraced backwards from end to start. The result is the shortest valid route between any two cities on the map.

JSON save system

Before making this system I relied on Unity's PlayerPrefs to store data, but PlayerPrefs is designed for simple key-value pairs like settings, not structured game data with nested objects. After adding cargo and an inventory system, where each cargo object and city had many values to store, I felt a custom save system was needed to make saving both easier and more reliable.

The system works by saving data into SaveData classes, which are stored inside SaveFile classes as lists. It creates a separate JSON file for each category of data, like cities, inventory, upgrades and passengers, keeping things organized so only the relevant file needs to be rewritten when something changes. These files are stored locally on the player's computer.

Cities are also stored in a dictionary keyed by city name, so any system can look up a city instantly rather than scanning through the whole list. SaveToDisk() is called at key moments like scene transitions and when the game exits. When the player starts the game, it reads the saved files and loads all the data back in.
